# jituan-PPT 集团PPT模板套用

把任意来源的 PPT（含文字、图片、表格）内容，**完整迁移并重新排版**到集团模板样式（`assets/集团模板.pptx`，源自 `D:\AIproject\模板.pptx`），输出正式、统一的集团风格汇报 PPT。

## 何时使用

- 用户提供一份现成 PPT/PPTX 或一堆内容材料，要求「按模板重排」「做成集团模板版式」「正式集团风格」。
- 只改版式风格，不改变内容逻辑结构：文字、数据、图片必须原样保留。

## 环境要求

- Windows + Python 3.9+，依赖：`python-pptx`、`Pillow`（用于图片尺寸）
- 安装：`pip install python-pptx pillow`
- **流程图 Visio 矢量渲染（v1.4，flow 版式默认启用）**：Windows + Microsoft Visio + `pywin32`
  （`pip install pywin32`）。Visio 不可用时 flow 版式自动回退为原生形状版式，不影响其余页面
- 渲染复核（可选，推荐）：WPS Office 或 Microsoft PowerPoint 已安装，能把 PPT 转 PNG 检查真实效果

## 标准工作流

### 第零步：清理原稿空文本框 / 空占位符（推荐）

源 PPT 常残留两类空壳形状：**空占位符**（PowerPoint 会画成虚线框并显示
「单击此处编辑内容」）、以及**无填充无描边的空文本框**（看不见但占位）。
转换前先跑：

```powershell
# 先看有多少（不改动文件）
python scripts\clean_empty_textboxes.py "<源.pptx>" --info
# 清理到新文件（默认 <源名>_去空框.pptx，不覆盖原稿）
python scripts\clean_empty_textboxes.py "<源.pptx>" --out "<任务工作区>\源_去空框.pptx"
```

规则（宁可漏删，不可误删）：

- 占位符：文字为空，或文字仅为占位提示语（「单击此处编辑标题/内容」「Click to edit …」）→ 删（图片/图表/表格类占位符保留，可能是待插图位）；
- 文本框（`cNvSpPr@txBox="1"`）：文字为空 **且** 无可见填充 **且** 无可见描边 → 删；
- 组合形状递归处理；其他自选图形（矩形/曲线/箭头等**装饰件**）无文字也**不删**——
  模板装饰块本来就没有文字，但有填充，一刀切会破版。

**清理范围覆盖三层**：幻灯片（slides）、版式（slideLayouts）、母版（slideMasters）。
页面上的空壳占位符若不删，会继承版式提示语；版式/母版里残留的提示占位符若不删，
未被页面覆盖的位置仍会显示「单击此处…」。脚本与 `build.py` 保存前清理都已遍历这三层。

默认**不覆盖原稿**，确认无误后才用 `--in-place`。
注意：`build.py` 保存前会自动再跑一遍同样的清理（见下条），所以成品页面上不会
再出现「单击此处编辑内容」。

### 第一步：读取源 PPT 内容（不遗漏）

1. 用 `read_document` 工具把源 PPT 转成 Markdown，**逐页读完**（每次 3~5 页，多页时分组读取）。
2. 记录：
   - 封面信息（标题 / 副标题 / 作者 / 日期）
   - 章节标题（目录或各页标题，**章节号按实际内容决定**：一章可能跨多页，多章可能共用模板页）
   - 每章的正文文字（要点 / 段落）
   - 表格数据（完整行列）
   - 图片（位置、数量、内容描述）
3. 需要图片素材时运行：
   ```powershell
   python scripts\extract_media.py "<源.pptx>" --out "任务工作区\media"
   ```
   按需加 `--page N` 只提某页；`--info` 可先看清单。
4. 章节结构自适应：源 PPT 的「一页=一章」或「一章=多页」都无所谓，**按语义归并章节**，写进 JSON 的 `sections`。

### 第二步：组织内容 JSON

按 `references/content-schema.md` 把内容整理成 `content.json`，要点：

- `cover`：标题必填，作者/日期尽量从源文件取
- `toc`：章节标题列表，**条数可增减（1~10 条）**，写在 `toc.items` 或直接给列表
  - ≤5 条：沿用模板实测坐标（不补空白条目）
  - 6~10 条：自动纵轴等距重排，编号沿模板弧线插值，版式仍属模板风格
  - 超过 10 条会截断（中文编号到「十」为止），需拆分或合并章节
- `sections`：逐页选择排版类型，**用 `chapter` 字段标注章节归属**（模板要求每章前有一页目录）
  - 数据表格 → `table`（整页表）或 `table_picture`（左表右图，最正式）
  - 要点罗列 → `bullets` / `bullets_picture`（左要点右图，支持多图：`images`）
  - 长段落 → `paragraph`
  - 大图 → `picture`；多图并排 → `gallery`
  - 前后对比（原设计 / 优化后）→ `compare`（左右两栏 + 中间现场图）
  - 工序链路 → `flow`（**v1.4 默认经 Visio 转矢量图插入**；支持 `stages` 分阶段结构，见下）
  - 排列图（帕累托）→ `pareto`（柱状频数 + 累计频率折线 + 双轴）
  - 对比两栏 → `split`
- 通用可选字段：`intro`（表/要点上方的引言行）、`note`（底部结论/注释条）、`col_widths`（表格列宽，英寸数组）
- `toc_transition`：默认 `true`。每章首屏用一个 `"chapter": 1 / 2 / 3 …` 标记，构建时自动在该章前插入一页目录并把当前章标题整条标红；不需要章节过渡页时设 `false`
- 图片路径写成 JSON 里实际可读的路径

**章节数与目录**：目录条数直接跟着章节数走，不必再为「超过 5 章」而删减内容。
真正超过 10 章（极少见）时，先 `question` 问用户合并方案。

> 例：3 章、每章 2 页
> ```json
> "sections": [
>   {"title": "1.1 项目背景", "type": "bullets", "content": ["..."], "chapter": 1},
>   {"title": "1.2 建设规模", "type": "bullets", "content": ["..."], "chapter": 1},
>   {"title": "2.1 工艺流程", "type": "bullets", "content": ["..."], "chapter": 2}
> ]
> ```
> 若 `sections` 页数与目录条数相等且都没写 `chapter`，默认「一页一章」，同样会生成章节过渡目录页。

### 第三步：生成

```powershell
python scripts\build.py "<任务工作区>\content.json" --out "<任务工作区>\成品.pptx"
```

输出命名建议：`<源文件名>_集团版.pptx`。

### 第四步：复核（必做，不许跳）

1. 数据自检：`build.py` 输出的统计与源内容核对（页数 / 章节数 / 图片数）。
2. 渲染复核（有 WPS/Office 时）：把成品转成 PNG，逐页看真实效果。
   可借助 render 方式：
   - 手动在 WPS/Office 打开另存 PNG；或
   - 调用 ppt-polish 的 scripts/render.py（若已安装该技能，本技能不重复实现）。
3. 用读图能力检查关键页（封面、目录、每个含表/图的正文页）：
   - 有无文字溢出 / 元素重叠 / 越界
   - 表格表头是否蓝底白字、行高是否合理
   - 图片是否等比、页面是否撑满
4. 发现硬伤 → 调整 JSON（加行/拆页/换类型；字号为硬规范 16/14 不调）→ 重新 build，直到合格。

### 第五步：交付

- 交付前跑一次 `python scripts\clean_empty_textboxes.py "<成品.pptx>" --info`，**应为 0 个空占位符 / 0 个空文本框**（build.py 已自动清理，这条是兜底复验）。
- 登记输出文件（result_file）。
- 汇报：完成页数、章节映射、图片/表格迁移数量、遗留问题（如缺失图片、超长文字被压缩）。

## 目录页机制（模板固定行为，必须保留）

原模板 `D:\AIproject\模板.pptx` 的结构是：**封面 → 目录(红第1章) → 第1章正文 → 目录(红第2章) → 第2章正文 → …**，
每章正文前都插一页目录，**当前章标题条整条标红（#FF0000、20pt、不加粗），其余条目文字统一白色（#FFFFFF，蓝底标题条上清晰；v1.4.2）**。

`build.py` 的实现方式：**整页克隆模板第2页的目录页原型**，再只改文字与红色，因此以下固定元素全部原样保留：

- 左侧浅蓝装饰块（FREEFORM，40% 透明）+ 贯穿的蓝绿装饰曲线
- 每个编号方块 = 阴影 PNG + 数字形状的组合（0.61×0.69，数字「一~十」）
- 透明装饰图（988×982）、辅助小额形、标题占位符「目录」

注意事项：

1. **不要自己重绘目录页**：用色块/圆角矩形拼出来的「类似版式」与原模板差异明显（原模板是曲线+阴影组合），一律走克隆；
2. 生成时模板自带的 11 页示例页会被清除，只保留目录页原型；原型页部件会改名为 `toc_proto.xml` 以免与新建页部件重名；
3. 克隆时**跳过 notesSlide 关系**：备注页只能属于一页，两页共用会让 PowerPoint 判定文件损坏；
4. 目录条目数 1~10 自适应：<5 条删多余条目，>5 条复制末条并沿原曲线等距插值（装饰曲线本身不延长）。

## 流程图 Visio 矢量集成（v1.4，与 visio-skill 同源的 Visio COM 能力）

`flow` 版式**不再用原生形状拼流程**，而是调用 `scripts/flow_to_visio.py`（本机 Visio COM 自动化，
与 visio-skill 技能同一机制）生成真矢量流程图：`.vsdx`（可在 Visio 中再编辑）+ `.emf`（矢量，
插入 PPT 无损缩放）。样式基准：`C:\Users\liuwust\Desktop\PPT\素材\设计后期管理流程.vsdx`。

| 元素 | 样式（基准文件实测值） |
|---|---|
| 流程步骤节点 | 直角矩形，填充 `#eceef6`，边框 `#3d64ac` 0.75pt |
| 阶段标签节点 | 直角矩形，彩色填充循环（`#b4a7d6` 紫 / `#f9cb9c` 橙 / `#ff9999` 红 / `#b5c7e7` 蓝 / `#99dfb9` 绿），边框 `#fe4040` 红色**虚线** 1pt |
| 节点文字 | 微软雅黑加粗 12pt 黑色居中（v1.4.2 起与全稿统一；不再沿用基准文件的宋体） |
| 连接线 | 黑色 0.75pt，实心三角箭头（EndArrow=4） |
| 布局 | 阶段标签沿左列竖排、竖线串联；步骤自左向右，超宽自动换行；画布 12.2″ 宽、高度自适应 |

实现机制：

1. `build.py` 的 `_layout_flow()` 遇到 `flow` 页时，把该页内容写成临时 flow JSON，
   子进程调用 `flow_to_visio.py` → Visio COM 生成 `.vsdx` + `.emf`；
2. EMF 以等比缩放插入正文区居中（不加拉边框），`.vsdx` 路径打印在构建日志中，可在 Visio 中再编辑；
3. Visio 未安装 / COM 调用失败 → 自动回退原生形状版式（圆角矩形+文字箭头），不中断构建；
4. 该页 JSON 加 `"flow_engine": "native"` 可强制走原生版式；节点字号 12pt 随基准文件，不随 16 号正文规范。

## 版式与文字排版规则（v1.4）

这些规则已在 `build.py` 内固化，改版式时别破坏：

| 规则 | 说明 |
|---|---|
| **字号硬规范（v1.4）** | **正文（要点/段落/对比/分栏/引言/注释条）一律 16 号微软雅黑；表格文字（表头+数据）一律 14 号微软雅黑**。不再按内容量自适应缩字号；溢出由 autofit 收缩兜底（表格行高预算仍生效，只压行高不压字号） |
| 页面垂直均衡 | 要点页 / 两栏页内容偏少时整体下移居中，避免全堆在页面上方、下方大片空白 |
| 注释条位置 | `note` 底边统一 6.40″（`NOTE_BOTTOM`）——页脚 5G 标识在 6.42″，再低就会压住水印；同时不得与正文/表格重叠 |
| 表格行高预算 | 表格 + 注释条必须落在 6.40″ 内：先压到最小行高（表头 0.36″、数据 0.30″），有余量再按比例分配；行数过多时整体等比缩 |
| 中文禁则 | 所有 run 打 `lang="zh-CN"`、段落加 `hangingPunct="1"`。**缺语言标记时 PowerPoint 不套用中文禁则**，会出现「。」单独占一行 |
| 单元格边距 | 表格单元格内边距收紧为左右 0.07″、上下 0.02″，否则默认边距会把行高撑大、注释条被挤到页外 |
| 封面 | 删除版式自带的正文占位符，只保留标题占位符 + 副标题/范围/日期文本框（否则出现「编制人：」空行、日期重复） |
| 空占位符清理 | `build.py` 保存前统一跑 `_strip_empty_shapes()`：删除**空占位符/提示占位符**（否则 PowerPoint 渲染成虚线框 +「单击此处编辑内容/标题」）和**无填充无描边的空文本框**；遍历 slides、slideLayouts、slideMasters 三层；有填充/描边的装饰形状一律保留 |
| 图片排布 | 左要点右图页：多图按长边方向判断——竖图并排、横图上下排；多图并排页（`gallery`）图注紧跟图片下方 |

## 陷阱与对策

| 坑 | 对策 |
|---|---|
| 章节跨页导致标题重复 | 语义归并，一个标题一节，不要机械按页号 |
| 源 PPT 图片在版式上(非页面) | extract_media 默认只提页面内图片，漏图时提示用户补充 |
| 源 PPT 残留空文本框 / 空占位符 | 跑 `clean_empty_textboxes.py`（--info 预览、默认输出新文件）；build 保存前还会自动清一遍 |
| 每页出现「单击此处编辑内容」虚线空框 | **版式/母版继承的空正文占位符**在 PowerPoint 里会显示提示语（python-pptx 读到的 text 是空串，极易漏检）。`build.py` 的 `_strip_empty_shapes()` 已在保存前删除页面、版式、母版三层的空/提示占位符；自定义脚本务必也做同样清理 |
| 表格超长 | 缩小字号到 11pt / 增加行高 / 拆列，保证一屏放得下 |
| 文字溢出标题条 | build.py 已做 autofit；仍溢出则精简标题（与用户确认） |
| 目录条数 | 1~10 条自动适配；≤5 用模板坐标，>5 等距+弧线插值；>10 需合并章节 |
| 目录页版式被重绘走样 | 一律克隆模板原型（曲线/阴影/装饰图无法用形状拼出同款） |
| 章间缺目录页 | section 加 `"chapter": k`；未标且页数≠目录数时只生成 1 张目录并提示 |
| 句号/标点单独占一行 | run 必须带 `lang="zh-CN"`（build.py 已统一设置）；手工加文本框时也要带，否则中文禁则不生效 |
| 注释条压住页脚 5G 标识 | 注释条底边固定 `NOTE_BOTTOM`=6.40″；表格页按行高预算先压缩表格 |
| 表格行被注释条压住 | 行高预算已含注释条高度；行数过多时自动等比缩，不要手工把 note 上移 |
| 模板文件被占用 | build.py 只读取模板，输出到新文件，不影响原件 |
| flow 页没走 Visio（日志出现「回退原生版式」） | 检查 Visio 是否安装、`pip install pywin32` 是否装到当前解释器；win32com 报 `no attribute 'CLSIDToClassMap'` 时删除 `%TEMP%\gen_py` 缓存目录后重试 |
| 表格 14 号后个别行文字被压 | 行高预算只压行高不压字号；行数过多时拆列或拆页，不要私自把字号降回去 |
| 正文 16 号后要点溢出 | autofit 自动收缩兜底；仍溢出说明内容过多，应拆页而非缩字号 |

## 禁止事项

- 不修改模板原文件（`assets/集团模板.pptx`），读取只读。
- 不改动源 PPT 原始文件（`clean_empty_textboxes.py` 默认输出新文件，`--in-place` 须用户明确同意）。
- 不丢失源内容（文字、图片、表格都必须迁移）。
- 不编造模板中不存在的版式/颜色。
- 不擅自为凑模板而删减章节；目录条数可增减，无需截断到 5 条。
