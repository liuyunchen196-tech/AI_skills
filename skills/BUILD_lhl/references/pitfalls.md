# 踩坑清单（pitfalls）

每条都是真实发生过的故障：**症状 → 根因 → 修复**。开工前扫一遍，能省半天。

---

## 一、环境与运行

### 1. `python` 解析漂移
- **症状**：同一个脚本在这个终端能跑、在 `启动.bat` 里跑不了；`ModuleNotFoundError: flask`
- **根因**：PATH 里有多个 Python，`python` 指向的未必是装了依赖的那个
- **修复**：一律显式使用
  `C:\Users\<user>\.workbuddy\binaries\python\envs\default\Scripts\python.exe`

### 2. `.bat` 双击没反应
- **症状**：双击 `启动.bat` 黑框闪一下就没，或报 `'或框、无需手动打开' 不是内部或外部命令`
- **根因**：bat 文件是 **LF 换行 + UTF-8 中文注释**，cmd 把行打碎后逐段执行
- **修复**：
  - 写 bat 必须 **CRLF + 纯 ASCII**
  - 用 `goto` 标签替代多行 `if` 块
  - Python 侧：`launcher.py` 里 `_redirect_std()`（pythonw 下 `sys.stdout is None`）、健康轮询、端口复用、失败弹 MessageBox
- **写文件代码**：
  ```python
  with open(p, 'w', encoding='ascii', newline='\r\n') as f:
      f.write(bat_text)
  ```

### 3. 端口被残留进程占着，接口一直返回旧数据
- **症状**：`/api/lean_meta` 永远返回 339 条，但 JSON 明明是 424 条
- **根因**：之前调试留下的 `pythonw.exe` 还占着 5099，加载的是旧 JSON
- **修复**：`Get-Process pythonw | Stop-Process -Force`，确认 `port free` 再启动
- **预防**：测接口前先探端口；`/api/meta` 返回里带上数据文件 `mtime`，一眼看出新旧

## 二、提取

### 4. `find_tables()` 对合并单元格表格失效
- **症状**：识别出的行错位、跨页表格顺序乱、单元格内容跑到隔壁列
- **根因**：PyMuPDF 的表格识别假设规整网格
- **修复**：改用**矢量框线法**（竖线定列、横线按 y 聚类且要求覆盖整宽）

### 5. 页面 `/Rotate` 90/270 导致图片坐标错位
- **症状**：裁出来的图是别处的画面，或图与措施对不上
- **根因**：`get_image_info()` 返回的是**未旋转坐标系**下的 bbox
- **修复**：对候选变换（原样 / 交换宽高 / 镜像）逐一试，取与框线最贴合的解

### 6. 扫描件 OCR 丢单字
- **症状**：措施名末尾少一个字，如「电梯轨道梁设计优」缺「化」
- **根因**：OCR 默认阈值把单字行当噪声过滤
- **修复**：`text_score=0.3, box_thresh=0.2`；名称列单独裁切、400dpi 重识别

### 7. OCR 把编号锚点当正文删掉
- **症状**：`1.3-2` 这类条目整条消失
- **根因**：过滤规则 `^\d+\.\d+\s*\S{2,10}$` 把编号当成正文段落
- **修复**：**含连字符的编号一律保留**；过滤正文改用「文本宽度 > 135pt」

### 8. 蓝色标题条被当成效果图
- **症状**：每张卡片的图片区第一张是纯色蓝条
- **根因**：标题条是背景图（约 429×40pt），也出现在 `get_image_info()` 里
- **修复**：按尺寸特征过滤；或用 `y1 > 100 且 y3 > 200 且 宽 > 50 且 高 > 60` 组合条件

### 9. 一页 3 卡（左 1 右 2）内容串卡
- **症状**：左卡的工艺要点跑到右卡，字段整体错位
- **根因**：只按 y 切片，没先按 x 分栏
- **修复**：先按 `x < width/2` 切左右栏，栏内再按 y 切卡片

### 10. 文本断行拼接出多余空格
- **症状**：`2 、对铝模安装工人进行交底` 中间多个空格；英文单词被粘连
- **修复**：中文不加空格；行首是序号（`1、`）或行尾是标点（`，。；：`）直接相接；
  正则归一 `(\d)\s+、` → `\1、`

## 三、数据

### 11. 写库脚本重跑导致数据翻倍
- **症状**：376 → 472 条，图片库多 158 张，出现 `xxx_2.jpg`
- **根因**：脚本无幂等保护，连跑两次
- **修复**：备份 → 按备份的图片引用集清理孤立文件 → 还原 → 只跑一次
- **预防**：`ingest.py` 写入前检查 `来源表` 是否已存在；执行前必 `cp lean_measures.json lean_measures.bak.json`

### 12. 字面相似度抓不住同义改写
- **症状**：`止水节预埋` 和 `止水节一次精准预埋` 相似度只有 0.23，被当成两条新记录
- **根因**：bigram Jaccard 对「插入修饰词」的长标题极不敏感
- **修复**：叠加「最长公共子串 ≥ 3 字」做候选，再**人工/Agent 逐条确认**，最后写 `merge_map.json`
- **经验**：64 条里 16 条真重复，全靠人工比对，纯阈值一个都抓不到

### 13. 优化效果重复 4 次
- **症状**：某条记录「优化效果」同一段文字重复出现 4 遍
- **根因**：重复单元格被多行合并写入
- **修复**：句子级去重（按 `；;。` 切分，去重后按原序重排），批量修过 214 条

### 14. 分部名不匹配标准树
- **症状**：校验报「不在标准树: 8」
- **根因**：写成 `室外工程`，标准树是 `室外工程（附录C）`
- **修复**：批量替换 + 校验归零

### 15. 优化类型分裂
- **症状**：`措施优化（永临结合）`、`措施优化（施工措施）`、`措施优化` 三种并存，统计表被拆成三行
- **修复**：归一为 `措施优化`，子类移入 `手册分类`

### 16. 一条措施 5~6 张图，PDF 只显示 4 张
- **症状**：图片区永远最多 4 张
- **根因**：`r['图片'][:4]` 硬截断
- **修复**：`[:6]`；>4 张时改三列缩略（`per_row=3, cw=4.8, chh=4.3`）
- **反面教训**：顺手把单图尺寸从 14.0×6.0 改成 6.0，页数从 205 涨到 335 —— **改布局参数要单独验证页数**

## 四、成果生成

### 17. `launcher` 导入失败
- **症状**：`AttributeError: module 'launcher' has no attribute 'start_server'`
- **根因**：启动器重写后不再导出该函数
- **修复**：改为 `from app import start_server`

### 18. 前端拿不到最新数据
- **症状**：工具端筛选结果比库少
- **根因**：`lean_lib` 有 `_cache`，进程内缓存不失效
- **修复**：改数据后重启服务；或给 `load_measures()` 加 `mtime` 检查

## 五、查重与合并

### 19. 「调阈值」解决不了查重
- **症状**：阈值 0.62 跑 376 条只报 1 组，而且「临边作业安全带挂点（一）（二）」是真不同做法
- **根因**：真重复往往「一条写一句、一条写五句」，覆盖率/序列比被长度差拉低，落在 0.35~0.55；
  而名字极像的不同构件反而相似度高
- **修复**：先**按分部分项排序通读全库清单**（`review_sheet.py` 出 xlsx），按业务判断逐组确认；
  算法只负责把「同分部分项 + 同部位」的记录排到一起，不做最终判定
- **数据**：376 条经人工确认合并 44 条（41 组），其中绝大部分算法根本没报警

### 20. 合并用的 id 必须是「合并前」的
- **症状**：按 decisions 执行后，`#12` 变成了完全不相干的措施，`别名` 记错
- **根因**：合并结束会 `id` 重排 1..N；拿重排后的 id 写第二份 decisions 就全错位
- **修复**：decisions 里的 `keep/drop` 一律取**执行前**那份库的 id；要二次合并先重新出候选、
  重新取号；不要手改 id

### 21. 名字像 ≠ 做法同：构件不同一律不并
- **症状**：差点把「构造柱 / 门过梁 / 门垛 / 上反坎 同主体一次浇筑」并成一条
- **根因**：四条的「优化内容」几乎一样（都是"随主体一次浇筑"），只是对象不同
- **修复**：判据里加一条硬规则——**不同构件不合并**；同理「预制 U 型砌块」用作线槽砖与过梁模板
  是两种用途，也不能并
- **留痕**：合并时把原名写进 `别名`，即使判断偏保守，检索也不会丢

### 22. 图片重复用 MD5 查不出来
- **症状**：`md5sum` 全不相同，但肉眼能看到同一张图出现多次
- **根因**：同一张图被不同批次重新编码/裁剪，字节不同、画面相同
- **修复**：**dHash**（缩到 16×16 灰度、比相邻像素），汉明距离 ≤26 判同图；阈值降到 18 复检无残留
- **产出**：本项目查出 12 组重复（8 组同一记录内、4 组记录重复、1 组配错图）

### 23. 删重复图把「唯一保留的那张」删了
- **症状**：合并后某些记录图片数变 0，文件还在但引用空了
- **根因**：先删「被并入记录的图」，再想从其中挑一张留 —— 挑的时候文件已经没了
- **修复顺序（不可颠倒）**：算保留清单 → 把保留项 `mv` 成 `__tmp_N.jpg` → 删除其余 → 改名回写引用
- **代码坑**：变量名别叫 `KEEP` 又当成「删除列表」用，本项目因此误删过一批不重复的 `_1`

## 六、发布打包（EXE / 网站）

### 24. exe 启动即崩：缺 reportlab
- **症状**：双击无反应，同级 `launcher_error.log` 里 `ModuleNotFoundError: No module named 'reportlab'`
- **根因**：开发机装了 flask/openpyxl/python-pptx/pillow，唯独没装 reportlab（PDF 用到时才 import）
- **修复**：`pip install reportlab`；打包前先 `python -c "import reportlab"` 自检

### 25. 打包后 PPT 生成失败：`sys.executable` 是 exe 本身
- **症状**：源码能出片，exe 里点 PPT 报「构建失败」，日志空
- **根因**：`generate_ppt()` 原来 `subprocess.run([sys.executable, build.py ...])`，
  冻结后 `sys.executable` 指向 exe，等于又启动一个自己
- **修复**：把外部技能脚本与模板复制进 `data/ppt_builder/`（随 data 打包），改为**进程内加载**：
  `importlib` 载入 build.py，临时改 `sys.argv` 调 `main()`，前后把 `sys.stdout/stderr` 指向
  devnull 再还原（`--noconsole` 下 `sys.stdout` 为 None，模块级包装 `sys.stdout.buffer` 会炸）

### 26. `--specpath` 让 `--add-data` 的相对路径失效
- **症状**：exe 起来 404，`static` 找不到
- **根因**：`--add-data static;static` 会按 **spec 文件所在目录** 解析，而 spec 在 build 子目录
- **修复**：`--add-data` 一律传**绝对路径**

### 27. 写库写进了只读的临时目录
- **症状**：导入 Excel 成功，重启后数据没了
- **根因**：`_MEIPASS` 是只读解包目录，写进去重启即丢
- **修复**：`_resolve_data_dir()`——冻结模式下把 `data` 解析到 **exe 同级**，首启复制一份可写副本

### 28. 覆盖旧 exe 打包失败
- **症状**：`PermissionError: [WinError 5]`，dist 目录写不进去
- **根因**：旧 exe 还在运行，文件被占用
- **修复**：打包前 `taskkill /PID <pid> /F` 或让用户关窗口；打包脚本里先探 5099 端口

### 29. 用户看不到日志
- **症状**：出错后 exe 旁边没有 log，无法排查
- **根因**：`launcher_console.log` 用 `HERE` 落盘，冻结后 `HERE` 是 `_MEIPASS`
- **修复**：日志路径改到 **exe 同级**；再挂 `threading.excepthook` 捕获请求线程里的未处理异常

## 七、前端交互与成果生成

### 30. 点完 PDF 就点不了 PPT
- **症状**：生成成功后弹全屏结果弹窗，关掉后格式卡片失效，回退重选也不行
- **根因**：结果做成 `position:fixed` 遮罩，挡住步骤 4 的格式卡片；且 Excel 走 tkinter 另存对话框，
  在窗口化程序里容易卡住整条流程
- **修复**：结果改为**步骤 4 内的内联绿色卡片**（含「打开文件 / 打开所在目录」）；
  Excel 与其他格式一样直接写 `output/`，不弹对话框；`enterStep4()` 重置状态但保留已勾选项
- **加固**：前端 `BUSY` 防重复提交 + 断线等 1.2s 重试一次；后端 `GEN_LOCK` 串行化，
  并发第二次返回 409「上一份成果仍在生成中」；文件名时间戳精确到**秒**

### 31. `Failed to fetch` 多半是服务端刚退出
- **症状**：前端 `catch` 里只显示 `TypeError: Failed to fetch`，后端日志没有任何记录
- **根因**：请求发给了**正在退出的进程**（例如测试实例刚被 kill），连接被中断
- **修复**：先看端口上跑的是哪个 pid、启动时间对不对；前端断线自动重试一次并把错误文案改成
  「确认程序未关闭，重开后重点一次」，不要直接把 TypeError 抛给用户

### 32. `-webkit-line-clamp` 漏半行残字
- **症状**：卡片底部浅色框里露出半行被切的字
- **根因**：clamp 加在带 `padding/border` 的盒子上，裁切按内容盒算
- **修复**：外层做容器负责 padding/边框，**内层 `.effin` 单独 clamp**

### 33. 改了 CSS/JS 用户还是看到旧的
- **症状**：改完样式，页面没变
- **根因**：浏览器缓存静态资源
- **修复**：`index.html` 里引用带版本号 `app.js?v=20261114a`，**每次改前端都 bump**

### 34. 无头截图误判「横向溢出」
- **症状**：`--window-size=390,844` 截图右侧被裁，以为手机端溢出
- **根因**：Windows 上 Edge 无头有**最小窗口宽度**（约 477 CSS px），设 390 会被裁
- **修复**：用 `document.documentElement.scrollWidth == clientWidth` 判定是否真溢出；
  截图改用 519 宽观察移动端布局

## 八、动作纪律

1. **先备份再写库**，任何 `ingest` / `add_columns` / 批量修正 / 合并之前。
2. **先出清单再动手**，查重、批量改字段都先出候选表。
3. **一次只跑一次**，脚本执行后核对条数，确认无误再进下一步。
4. **改完必校验**，跑 `validate.py` 七项，不全绿不算完成。
5. **素材只读**，永不修改 `素材\` 下的原始 PDF。
6. **交付前空目录试跑**，exe 与网站包都要在干净目录验一遍再给用户。

## 十一、通用解析与多板块架构（2026-11 新增）

**P35 字体缺 ToUnicode：文本层是乱码，不是"提取失败"**
症状：`page.get_text()` 返回 `"XaXXffiXXfMfSffiaitXiiiX#"` 这类大小写混杂、无空格的字母串。
判定：`cjk/len < 0.05` 且 `alpha/len > 0.4` 且 `大写/字母 > 0.22`（或常见英文词 < 2 个）。
处理：整页跳过 + 汇总提示 `N 页乱码，建议 OCR`；如果全篇乱码，直接 raise 让调用方引导用 OCR 技能。
**不要把乱码写进库**——脏数据比空库更难清理。

**P36 半页/通栏大图是扫描层，不是案例图**
`page.get_images()` 常返回覆盖半页的位图（版式底图或扫描层）。只按面积 > 92% 过滤不够。
追加：`rect.height > 页高*0.7 or rect.width > 页宽*0.7` → 跳过。真正的插图通常在 20%~45% 面积。

**P37 表格首行不一定是表头**
复合表常见结构：第 0 行是分组标签（每建必优评估/标准化建造/工序分解…），第 1 行才是列头。
做法：在前 4 行里选"命中表头词最多"的行（序号/名称/规格/部位/数量/内容/路径…），它之前的行全部丢弃。
跨页续表没有表头行时，沿用前页的 canonical 表头，否则会把数据行当列名。

**P38 双栏重复表：一行要拆成两条**
表头形如 `序号 部品名称 规格 附图 使用部位 | 序号 部品名称 规格 附图 使用部位`，数据行左右各一条。
检测：`n % k == 0` 且 `header[i] == header[i+k]`（k 为半段列数）→ 每行按 k 切片。
拆完过滤：非表头行至少要 2 个非空单元格，否则是跨栏说明文字（"安全防护固定点"），应丢弃。

**P39 目录页会把条目数翻倍**
索引/目录页常被识别成表格或卡片，页码混进正文。
表格路径：数据行里 ≥55% 带编号（`[A-Za-z]{1,4}-\d{1,4}`）→ 判为目录跳过。
卡片路径：一页全是 `1.xxx 页码 2.xxx` 清单且无图（≥6 行）→ 跳过。
也要认"目 录 / CONTENTS"字样（前 400 字内）。

**P40 卡片版式别当表格解析**
一页 2~6 张卡片时，`find_tables` 会把"实施效果/工艺要点"两栏当成 2 列表格，解析出满屏碎片。
路由规则：`列数>=4 且 数据行>=3 且 表头命中>=2` 才算数据表；否则按卡片切：
取页面最大字号且长度 4~46、非固定标签（标准化建造/实施效果/工艺要点…）的行作标题，
其余文本按坐标归到最近的上方同栏标题，图片按 y 归卡。

**P41 Windows 上 `shutil.rmtree` 删几百个文件会把主线程卡死**
发布前清空旧 `网站发布/`（500+ 图片）时，rtree 可能阻塞数十秒到数分钟（索引/杀软扫描）。
改法：`os.rename(stage, stage + '_old_' + 时间戳)` 立刻腾出路径，再起 daemon 线程异步删。
zip 覆盖同理：删不掉就 `os.replace` 成 `.old`。

**P42 快照和转换结果必须分目录**
通用中心把**原始快照**写到子项目 `data/factory/<key>.json`；
子项目把**转成本项目结构**的结果写 `data/factory_items/<key>.json`。
两者混在一个目录 → 第二次同步会把第一次的数据集文件覆盖（曾出现"63 条 + 36 条"只剩 36 条）。
静态站生成器读 `data/factory/`（有 `records/columns`），子项目业务读 `data/factory_items/`。

**P43 子项目自带 `build_release.py` 的输出目录可能不同**
它常写死 `../成果发布`，而通用打包器预期 `<项目>/成果发布`。
不要硬传 `--out`（老脚本不解析参数会报错）：读脚本前 4KB 判断有无 `--out` 再决定是否传；
打包后扫描 `<项目>` 与 `<上级>/成果发布` 里 40 分钟内最新的 exe，复制到统一位置。

**P44 多线程 Flask + SQLite：连接不能跨线程复用**
`check_same_thread=False` + 全局 `RLock`，每次操作开新连接（WAL 模式），不要缓存 connection。
后台任务线程写 job 状态时尤其容易撞锁，写操作一律走同一把锁的 `x()`。

**P45 前端加 hash 路由，截图与书签都省事**
单页多 tab 时把 `location.hash` 与 tab 同步（`#dataset` / `#map` / `#pub`），
启动时读 hash 定位。无头浏览器截图可直接指定 hash，不用模拟点击。

## 十二、手动录入与目录迁移（2026-11-14 新增）

**P46 `fetch` 带 body 但没写 method → 浏览器直接拒绝**
症状：点保存弹 `Failed to execute 'fetch' on 'Window': Request with GET/HEAD method cannot have body.`
原因：封装 `api(path, {body})` 时只合并了 body，没给默认 method，`fetch` 按 GET 发。
修法：在封装里 `if (o.body && !o.method) o.method = 'POST';`。别指望每个调用点都写 method。
这类 bug 只有真实点击才暴露（curl 直接发 POST 不会复现），必须用 CDP/浏览器跑一遍点击流程。

**P47 迁移目录后 SQLite 里的绝对路径静默失效**
`images.path` / `sources.path` 存的是绝对路径，换根之后不会报错，只会表现为
「缩略图 404」「同步时图片没拷过去」「删记录不删文件」。
批量改也别用 `LIKE 'D://旧//%'`——反斜杠在不同层（bash heredoc / JSON / SQL）转义不一致，
实测出现过把 `\` 变成 `//` 导致 0 命中。可靠写法：取 `os.sep+'data'+os.sep` 的位置切尾巴再拼新根，改完断言「缺失文件数 = 0」。

**P48 迁移后通用中心找不到子项目清单**
`discover_targets()` 原来只认 `dirname(db.ROOT)/config/subprojects.json`；
分文件夹后配置在 `<平台>/门户/config/`。改成候选链：`HUB_HOME` 环境变量 → `<上级>/门户` → `<上级>` → 同级任意子目录；
并在门户 `hub_lib.start()` 里注入 `HUB_HOME`。

**P49 复制项目时把中间产物一起搬**
`build/ dist/ build_release/ __pycache__/ *.log`、`网站发布_old_*`、exe 运行生成的 `data/` 都不该进新仓库，
否则 100MB 的东西搬成 350MB，还容易让「启动.bat 优先跑 dist 里的旧 exe」这种坑复活。
顺带：`启动.bat` 别优先 `dist\*.exe`，冻结版改了源码不会生效，日常维护应优先 `python launcher.py`。
