# 分部分项口径（divisions）

标准树见 `assets/divisions.json`，来源 **GB 50300-2013《建筑工程施工质量验收统一标准》附录 B、附录 C**。
每条措施必须落到「分部 / 子分部 / 分项」三级，**不允许只写分部**。

## 二、判定决策树（按顺序问）

```
1. 这条措施发生在「施工临时设施 / 安全防护 / 机具 / 管理手段」上吗？
   → 是：分部 = 措施项目（虚拟分部，见第四节）
2. 发生在结构成型阶段（模板/钢筋/混凝土/砌体）？
   → 主体结构
3. 发生在装饰面层（抹灰/地面/门窗/涂饰/幕墙）？
   → 建筑装饰装修
4. 是机电管线/设备（给排水、暖通、电气、智能化）？
   → 对应 05/06/07/08
5. 是屋面构造（找坡/保温/防水/瓦面）？
   → 屋面
6. 是电梯本体安装？
   → 电梯
7. 在建筑之外（道路/围墙/室外管网）？
   → 室外工程（附录C）
```

## 四、「措施项目」虚拟分部

国家标准树里没有「措施项目」，但它承载了大量精益建造内容（安全、绿色、智慧、机具、临设）。
工具端 `lean_lib.py` 用 `tree.setdefault('措施项目', OrderedDict())` 把它挂到树末尾。

**校验时它算合法**，不要报「不在标准树」。
子分部/分项命名必须从 `schema.md` 第四节的清单里选，不新造词。

## 五、映射脚本的写法

```python
RULES = [
    (['铝模','木模','模板','支模'], '主体结构', '混凝土结构', '模板', '全楼层'),
    (['免抹灰','压槽','收口'],     '建筑装饰装修', '抹灰', '一般抹灰', '内墙'),
    # ... 具体在前，宽泛在后
]
OVERRIDES = {  # 规则命不中或命中错时逐条指定
    '三段式止水螺杆施工工艺': ('主体结构','混凝土结构','模板','地下室外墙'),
}
```

- **先具体后宽泛**：`['悬挑架']` 必须排在 `['架']` 之前
- 命中即停，不累加
- 兜底：按 `优化类型` 给默认归属，但必须在校验里列出兜底条数，人工过一遍
- `OVERRIDES` 是逃生门，宁可写 20 条覆盖，也不要让规则互相打架
