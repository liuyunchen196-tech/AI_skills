# 单页知识库构建器：多库架构 + 内容分片 + 三轨导出

> **v2.2.1 修复**：检索引擎**键与查询统一小写口径**——查询进引擎前已被 `toLowerCase()`，而词表的键保留原样，
> 于是**含拉丁字母的键（`N+1` / `2N` 这类）此前完全匹配不上**，表现是「扩展词为空、首位落空」，
> 看着像「库里没有这个内容」，其实是键根本没被匹配到。同批在语义层补三条经验：
> **词表「缺键」比「缺值」隐蔽**（有 `法院` 却没有 `检察院` 就是典型漏网）、
> **映射值与查询字面重合会被 `add()` 跳过**（所以配 `['A','B']` 给「A 和 B 有什么区别」等于没配）、
> **判「库里没有」之前先分清「没有内容」还是「没有入口」**。
>
> **v2.2 新增**：**打包工序**——把几十上百个散装 `<script src>` 合成 `bundle/` 下十来个文件，
> 页面从 135 个请求降到 11 个；同时立三条改库期纪律：**源文件是唯一数据源**（bundle 是生成物）、
> **幂等重建 + 等价性自检**、**校验器读源文件所以「三件套全绿」不等于页面是新的**。
> 新增防坑 **坑十六**（三种节写法并存，往单行字符串插块会白屏）、**坑十七**（忘重建 bundle 的假绿灯）、**坑十八**（校验器读 A、页面读 B）、**坑十九**（改了命名规则，`index.html` 还指旧名 → 全站检索静默失效）。
>
> **v2.1 新增**：语义层**引擎与词表分层**（引擎领域无关、词表按领域各写一份）、
> **四路扩展带置信权重**、**原文命中分档**（治汇总页霸榜）、**通用疑问只作强化**（治泛词顶翻正解）、
> 指路节折让收紧到 0.2，并固化「改完必回归」纪律。
> **v2.0 新增**：单库 → **多库**（一套引擎挂 N 个库、库间深链接互跳）、**三套功能轨道**、
> **时效标注硬拦截**、**跨库链接校验**，以及**运维期**才暴露的第二批坑。
> v1.x 的单库流程依然成立，多库是它的超集。

> 一次投入，两种产物：**能双击打开、能搜能跳的 HTML 应用** ＋ **能导入知识库的 Markdown**。
> 两者同源，改一处内容两边同时更新。

## 适用场景

用户说这些时启用：

- 「帮我体系化整理 XXX，形成一套知识学习库」
- 「把资料做成能查、能搜的工具」
- 「做成离线知识库，不要联网」
- 「顺便导出一份 Markdown，我要传到知识库里」

**判断标准**：内容体量大（预期 5 万字以上）、结构清晰（有分组与条目）、需要长期反复查阅、且用户可能需要导入其他知识系统。三条里中两条就该用本技能，而不是塞进一个聊天回复或一份长 Word。

## 架构：内容与引擎分离

```
<项目>/
├── index.html          ← 引擎（导航/检索/路由/打印样式），一次写好基本不再改
├── data-<域>.js        ← 内容数据，分片
├── data-<域>2.js       ← 分片 2（超出单次写入上限时）
├── figs<N>.js          ← 图示数据，分片（可选层）
├── figs-map.js         ← 图示安放映射 + 图示册索引（可选层）
├── export-md.js        ← 导出脚本（含 HTML→Markdown 解析器）
├── export-figs.js      ← 图示导出脚本（独立 SVG / PNG / 图示册）
├── export-slides.js    ← 投屏课件导出脚本（可选层）
├── build-bundle.js     ← 打包脚本：把散装 data-/figs-/syn- 合成 bundle/（源文件仍为唯一数据源）
├── bundle/             ← 生成物（不要手改，由 build-bundle.js 重建；页面只读这里）
├── kb-config.js        ← 共享配置层：各脚本从这里取「库清单 / 标签」，不写死库名
├── kb.config.json      ← 本项目私有值（库显示名、输出文件名、图示标签）※不随包发布
├── project-checks.js   ← 本项目私有校验断言（迁移完整性、subtitle 口径…）※不随包发布
├── md/                 ← 导出产物：全量 + 分节（+ 图示/）
└── 专题课件.html        ← 投屏课件产物：单文件、离线、可打印（可选层）
```

数据文件统一结构：

```js
window.XXX_DATA = {
  tab:'标签名', badge:'law', title:'库标题', desc:'一句话定位',
  subtitle:'适用范围与口径', homeTitle:'总览',
  footnote:'免责与口径声明',
  groups: [ { title:'一、分组名', sections:['sec-id-1','sec-id-2'] } ],
  sections: {
    'sec-id-1': { title:'', icon:'', level:'', tags:[], desc:'', html:`<p>…</p>` }
  }
};
```

分片合并（放在 `index.html` 里，必须在读取 `LIBS` 之前）：

```js
(function(){
  var P = window.XXX_DATA; if (!P) return;
  [window.XXX_DATA_2, window.XXX_DATA_3].forEach(function(part){
    if (!part || !part.sections) return;
    for (var k in part.sections) P.sections[k] = part.sections[k];
    if (part.isFinalGroups && part.groups) P.groups = part.groups;   // 关键
  });
})();
```

**分片时只有最后一个分片带 `isFinalGroups: true` + 完整分组列表**，其余分片只放 `sections`。否则分组顺序会错乱（按合并顺序拼接，跨分片的分组会跑到末尾）。

## 多库架构：一套引擎挂 N 个库（v2.0）

内容多到一定程度，一个库装不下的**真正原因往往不是体积，而是视角**。实战拆法（可照搬）：主规则库（规则本身）、执行库（怎么落地）、图示册（一页一图）、案例库（真实案例与人）、衍生创作库（基于内容再加工）、机构制度库（这些都是什么机关）、流程库 A（一件事从头到尾）、流程库 B（另一条线）。

**判据：一个库只回答一类问题。** 读者问「法院和检察院有什么区别」和「我的案子进去以后第几天会被批捕」，是两类问题，塞进一个库会让两边都讲不透。八个库合并成一个 241 节的巨型库，等于把图书馆的分区拆掉、把所有书堆进一个大厅。

### 库序即契约，新增库一律追加到末位

深链接格式是 `#<库下标>/<节id>`，**下标写死在内容里**。所以：

- **新库必须追加在末位**，不能插在中间——插一个，后面所有库的既有深链接全部错位，且**不报错**（链接校验只看目标 id 存在与否，看不见下标漂移）。
- 图册的下标若固定为 2（`ATLAS_IDX`），也要让它一直占着第 2 位。

### 每个库的末片编号必须最大

`_1 / _2 / _9 / _99` —— 末片（带 `isFinalGroups`）的编号要大于该库所有内容分片。新增内容分片后，末片编号不够大就得**重命名末片**（本次 `data-xxx22.js` → `data-xxx99.js`）。判据：合并是按数字序收分片的，末片排在最后，它的 `groups` 才会覆盖前面所有分片的分组。

> **分片命名必须是纯数字后缀**（`data-topicA25x.js` 会因 `/_\d+$/` 不匹配而在合并时被整个丢失，且不报错）。

### 新增一个库要同步改六处（漏一处就挂载不上）

| # | 文件 | 改什么 |
|---|---|---|
| 1 | `index.html` | ① `<script>` 分片标签（内容分片按数字序在前、**末片最后**）② `merge(window.X_DATA, shards('X_DATA', window.X_DATA))` ③ `LIBS.push(window.X_DATA)`（**必须在末位**）④ `:root` 主题变量 + `.badge-lib` 配色 |
| 2 | `check-data.js` | `LIBS` 数组 + `TRACK_LIBS` 数组 |
| 3 | `check-figs.js` | 库列表元组 `[[rootKey, prefix], ...]` |
| 4 | `export-md.js` | collect merge 段 + `dump()` 调用 + 分节 forEach 数组 + `console.log` |
| 5 | `export-slides.js` | `LIB_OF` 映射 + `deckCss` 里该类库的 `data-accent` 与配色——**漏了配色，课件里这一库会用默认蓝色** |
| 6 | `README.md` | 文件说明表（分片清单）——**这项最容易漏** |

改完跑 `check-links.js`，新库的跨库链接目标要一并校验。

### 三套功能轨道：每个库都必须同时具备（硬拦截）

这是 v2.0 最重要的一条纪律。每个库必须有三条轨道，缺一条校验直接退出：

| 轨道 | 判据 | 回答什么 |
|---|---|---|
| ① 正文轨道 | 库有 sections | 库的主体内容（天然具备） |
| ② 总导读轨道 | `level`/`title` 含「导读」 | **本库怎么读、先读什么**——结构、按身份的阅读路径、贯穿主线、最短入门清单 |
| ③ 速查自测轨道 | `level`/`title` 含「自测」/「速查」 | **问—答—依据**形态，可当课堂提问或自学自测 |

**关键纪律：新建库时必须在同一批次内把 ②③ 一并补齐，不要留到下一轮。**
新库通常是从别的库迁来的正文——**天生不带导航节**，建完就必然「两条轨道空着」，下一轮审计必被列为缺口。

**形态辨别（易误判）**：以下是**流程工具**，**不算**速查自测轨道，不能用来顶替：
- 「发布前审核清单：24 项逐条打勾」——逐条打勾的检查表
- 「判例库使用指南与自测清单」——只覆盖库内局部，不是全库自测

### 跨库链接：让「八个文件夹」变成「一张有路的地图」

正文里直接写 `<a href="#6/lib-b-lodge">`，引擎接管所有 `a[href^="#"]`，不需要额外配置。但要做「去另一个库看这件事」的入口，用导览块，不要只写「详见某库」：

```html
<div class="xlib"><div class="xt">🔗 标题</div><div class="xi">
<a class="x-lib-b" href="#6/lib-b-lodge"><span class="lb">库名 · 视角</span><span class="nm">节标题</span></a>
</div></div>
```

**写完必跑 `check-links.js`**：跨库链接写错了**不报错**，只会在点击时静默无反应——这是最隐蔽的一类失效。

**判一体化程度要看双向矩阵，不能只看总数。** 只看「被引用总数」会漏掉两类结构性问题：

1. **入站链接全来自导航节** —— 本次实测某库 9 次入站**全部**来自导航节与入口表，**正文叙事里一条都没有**，读者在读具体流程时跨不回去。补法：在**流程叙事的具体环节**补入口，而不是再加导航节。
2. **某库「只进不出」（发出 0 条）** —— 读者进去就出不来，是地图上的死胡同。补法：在**该库自己的导读节**加一节「往上游/往下游看」。

> 审计做法：照抄 `check-links.js` 的加载方式（`global.window={}` + `new Function(src)()`），按库聚合节后逐节扫 `href="#N/id"`，统计**来源库 × 目标库**矩阵。

### 多库的分工口径：先划清再动手

本次确立的判据，值得照抄：**「X 是个什么机关、制度怎么来的」与「案子进去以后一步步怎么办」是两件事，应当分库**。前者是组织与制度史（上帝视角），后者是办案流程（含流程步骤表 + 法条依据 + 期限节点）。两库交叉深链接，不迁节、不改旧库。

另建一个**总入口节**（放其中一库，刻意排在全部内容之前）：多库地图 + 按身份的几条阅读路线 + 「同一问题多角度」对照表。

## 图示层：矢量教学图（可选但强推荐）

图文分家、图内嵌正文是最稳的形态：**图是独立数据，正文只认章节 id**。据此加三个文件角色：

```js
// figs3.js —— 图示分片（一个分片放 5—8 张）
window.FIG_DATA_3 = {
  figs: {
    'fig-topicA-flow': {
      t: '刑事程序流程',                 // 图题
      kind: 'law',                       // law | police，决定配色与角标
      sens: false,                       // true = 敏感图文，渲染时自动加「已打码」标记
      cap: '立案—侦查—审查起诉—审判的推进关系…',  // 图注：读图要点
      teach: '讲这一节时先讲左侧入口…',          // 课堂用法：老师怎么用这张图
      svg: `<svg viewBox="0 0 680 320" xmlns="http://www.w3.org/2000/svg">…</svg>`
    }
  }
};
```

```js
// figs-map.js —— 图放哪 + 图示册目录
window.FIG_MAP = {
  'topicA-proc': [ { f:'fig-topicA-flow', after:'二、程序推进' } ]   // after = 目标 h2 里的关键词
};
window.FIG_ATLAS = {
  tab:'图示册', title:'图示册', homeTitle:'图册总览',
  sections:{},                                   // 保留空对象，复用路由与检索逻辑
  subtitle:'共 <b>N 张</b>矢量图形…', footnote:'…敏感内容已打码…',
  groups:[ { title:'一、总论与基本概念', figs:['fig-topicA-pyramid','fig-topicA-parts'] } ]
};
```

引擎侧只需在 `index.html` 里加：`shards('FIG_DATA')` 合并 → `LIBS.push(FIG_ATLAS)` 注册第三个标签页 → `injectFigs(secId, html)` 在渲染章节处按锚点插图 → `figBlock(fid)` 统一卡片样式 → `renderAtlas()` 出图示册页。**新增图示只改 `figsN.js` + `figs-map.js` 两个数据文件，不碰引擎。**

**深链接要支持图 id**：路由里除了 `#<库序>/<节 id>`，还要认 `#<图册序>/fig-xxx` 并滚到该图——写文档时很容易漏掉这一条，结果图谱里贴出去的链接点开只到图册首页。`figBlock()` 渲染的 `<figure>` 带 `id="fig-<fid>"`，路由里判断前缀后 `renderHome()` 再 `setTimeout` 滚到锚点即可（章节页与图册页不会同时渲染，id 不会重复）。

资产导出（`export-figs.js`）：独立 SVG（`md/图示/NN_标题.svg`，可直接拖进 PPT/Word）、图示册 Markdown 索引、可独立打开的 `图示册.html`；加 `--png` 参数可再出一套 PNG 位图（走本机 Edge 无头截图，零额外依赖）。

**打码标记必须落在文件名上**：`sens: true` 的图，导出文件名一律追加 `_已打码`（由 `figFileName()` 判断 `F.sens` 自动补，**不依赖作者在标题里恰好写了「打码」**）。否则标题里没提打码的那张，从文件名上看不出是敏感题材，课件侧就分不出来。`export-md.js` 里的 `figFile()` 必须用同一套规则，两处不一致会导致 Markdown 里引用的图示路径不存在。改名后**旧位图会残留**，脚本会在收尾时比对「位图数 vs 图示数」并报出差异，不静默。

**配图分两批的定式：主线时间轴 ↔ 结构剖面。** 一个组（尤其是编年型、制度型的题材）配到 10 张以上时，不要混着放，分成两片、挂到不同小标题上：

| | 第一批 `figs<N>.js` | 第二批 `figs<N+1>.js` |
|---|---|---|
| 回答什么 | 这是哪一段 | 它里面长什么样 |
| 形态 | 时间轴 / 沿革链 / 阶段表 | 结构剖面 / 逐条对照 / 机构拆解 |
| 挂点 | 沿革叙述的小标题 | 制度分析的小标题 |
| 课堂用法 | 先定位坐标 | 再展开内部 |

**两批必须挂在不同小标题上**（`FIG_MAP` 的 `after` 各指一处），否则同一节里两张图会挤在一屏。反过来，**同一小标题挂两张图是允许的**——引擎按声明顺序依次追加到该小节末尾，两张就一前一后落在同一处，投影时一页一图。
图号仍然遵守「新图一律追加到新板块」，既有图号一个不动。

## 第三轨：单文件投屏课件（可选层）

**适用**：内容已经成型，需要拿到教室 / 会议室**直接讲**，而不只是"能查"。

**产出**：一个 `.html` 文件。双击打开、离线可用、`← →` 翻页、`F` 全屏、`P` 打印（选「另存为 PDF」即得可打印讲义）。拷到 U 盘或别人机器上直接能开。

**为什么用 HTML 而不是 PPT**：内容与配图已经都在 `data-*.js` / `figs*.js` 里，脚本能直接读——改一处内容、重跑一次脚本，课件跟着变，**不存在两份材料互相对不上**。分工是：**对外汇报要套模板 / 动画 → 用真 PPT（`tencent-pptx`）；内部讲授、图多表多、要随时跳回知识库核对 → 用本层。**

### 四个设计要点（缺一个都会返工）

1. **版式复用 `index.html` 的 `<style>` 块**——构建时把它读出来内嵌，而不是另写一套 CSS。这样课件与知识库天然同一套视觉；库里改了配色，课件重跑就跟着变。课件专属布局才写在自己的 `deckCss` 里。
2. **单文件、零外部依赖**——图是内联 SVG，字体用系统字体栈，不引 CDN、不引外部图片。
3. **一屏一块，表格与卡片块绝不被切开**。
4. **每讲先给一张导览页**（大序号 + 标题 + 领读段 + 本节路线 chips），再进内容页，最后是配图页；配图页带图注与「课堂用法」。页脚显示「当前页 / 总页数」，顶部进度条随库换色。

### 分页算法：软换页（页数能不能用的关键）

第一版用「每个 `h2` 强制新页、`h3` 也强制新页」→ **10 节出了 152 页**，半空屏特别多，投影时一直在翻页。
改成**软换页**后 → **101 页**。10 节 ≈ 100 页，即**每讲 10 页左右**是投影的合适密度；**超过 15 页/讲就说明阈值定小了**。

```js
const BUDGET = 820;   // 单页内容上限（权重）
const SOFT   = 340;   // 软换页阈值：小节没铺满 SOFT 就接着排在同一页
/* 同一页里出现的后续 h2 降级为 <h3 class="sh2"> 小标题，不再强制换页 */
```

权重口径（估算即可，不必精确）：表格按 `行数 × 34 + 40`，卡片块按 `正文字数 + 30`，列表按 `条数 × 26 + 20`，段落按 `字数 + 12`。

### 两个必踩的坑

- **「（续）」标记不能直接改写 `title`。** `title: cur.title + '（续）'` 在连拆四页时会产出「……（续）（续）（续）」。要同时存三个字段：`base`（原始小节标题）、`title`（渲染值）、`rooted`（本页标题是否来自本页的 `h2`——没有 `h2` 的续页不加「（续）」）。
- **`flush()` 会把 `cur` 置空**，所以 `cur = { title: cur.title, … }` 会 `TypeError`。必须先把 `title` / `rooted` 存进局部变量再 `flush()`。这个错误会在「`h3` 分支」和「溢出分支」**各犯一次**——两个分支写完都要单独检查。

### 验收（无头渲染数出来，不靠肉眼）

```
slide 数        = 总页数显示值          ← 不等说明有页没渲染出来
表格数          = 范围内各节 <table> 总数  ← 少一个就是有页被切开
配图槽数        = FIG_MAP 里该范围的挂载数
无 [object Object]                      ← 有则存在未取值的字段
```

> 表格数这一条最有用：**本次 61 个表格与 10 节的 `<table>` 计数完全相等**，一次就证明内容一个没丢。这比翻页看几十屏可靠得多。

## 八个必须绕开的坑

### 坑一：大内容一次性写入会被截断

单次文件写入有实际体积上限。经验阈值：**单个 `data-*.js` 控制在 60 KB 以内**。超过就分片。

症状：写入工具报参数错误，或文件只有前半段。**发现截断后不要重试同样的内容**——直接分片，这是最快的修复路径。

一节的合理体量：正文 800—1500 字 + 2—4 张表 + 3—5 个卡片块，对应源文件约 3—5 KB。**一个分片放 6—10 节最稳妥。**

### 坑二：正则切 HTML 做 Markdown 转换会静默出错

这是最隐蔽的坑——**转换会成功、文件非空、目录正常，但内容在嵌套结构处被吃掉**。实测踩到的三处：

| 正则写法 | 出错位置 | 表现 |
|---|---|---|
| `<div class="blk">([\s\S]*?)</div>` | 块内有 `<div class="bt">标题</div>` | 卡片在标题处被截断，**正文全部丢失**，且不报错 |
| `<li\b[^>]*>([\s\S]*?)</li>` | `<li>` 内嵌 `<ul>` | 外层 li 在第一个内层 `</li>` 处结束，嵌套列表降级成散落段落 |
| `<ul>([\s\S]*?)</ul>` | `<ul>` 内嵌 `<ul>` | 在第一个 `</ul>` 处截断，后续 li 全部脱离列表 |

**结论：必须用真正的解析器。** `scripts/export-md.js` 内含一个约 100 行的极简 HTML 解析器（标签栈 + 递归渲染），已正确处理上述全部情况。不要为了省事退回正则。

另一个易忽略点：含块级子元素的 `<div>`（如 `<div class="row"><b>事实</b>…</div>`）应合并成**一个段落**，否则会被拆成多行。判据是 `hasBlockChild()`——div 的子节点里没有 `p/ul/ol/table/div/h*` 时按行内内容整体输出。

### 坑三：分组与内容 id 会脱钩

最容易发生、也最难肉眼发现：**改了 section 的 id，忘了同步 groups 里的引用**，页面表现为点进去空白或直接跳回首页。

必须脚本校验，四项一起查（见 `scripts/check-data.js`）：

1. 语法：每个 `data-*.js` 能否 `new Function()` 执行通过
2. 正向：`groups` 引用的每个 id 在 `sections` 里都存在
3. 反向：`sections` 里定义的每个 id 都被某个 `groups` 引用（定义但未挂载 = 写了等于没写）
4. 结构：`<table>` 与 `</table>` 数量配平、无残留残片
5. **统计口径**：脚本里凡有"按下标切区间"的地方（如"第 10 组往后算作判例库"）都要复核

**第 3 项（反向校验）最有价值**——它抓的就是"新写了一节但忘了加进导航"这类错误。

**第 5 项是追加内容时才会暴露的坑**：本次实测校验脚本用「组十往后全部算判例库」来统计子库规模，追加一个**不属于判例库**的新组之后，统计立刻虚高（报成 18 组 39 节）。**追加内容前先扫一眼校验脚本有没有按下标切区间的逻辑**；有就改成「先按标题过滤、再切片」——按下标切的口径在追加面前一定会失效。

### 坑四：`html` 用双引号字符串装，会被 HTML 属性引号打断

`html` 字段里必然有 `class="blk note"` 这类属性。如果外层用双引号字符串包裹（`html: "<div class=\"blk\">"`），一旦漏转义就**直接语法错误**；而 `title` / `desc` 这类元信息字段里写中文引号（`desc: "……"统一审核"……"`）同样会打断字符串，且**看起来完全正常**、极难肉眼发现。

**做法：`html` 一律用反引号模板字符串**（`` html: `<div class="blk note">…</div>` ``）。属性里的双引号不需要转义，可读性也好得多。两个注意点：

- 内容里不要出现反引号和 `${`（模板里出现会被解释）；
- `title` / `desc` / `tags` 等元信息字段如果用双引号字符串，**内部引用一律用中文引号「」**，不要用英文 `"`。

> 注意：导出脚本 `export-md.js` 的属性解析依赖 `class="…"` 的双引号形式，所以**只放宽 JS 字符串的写法，HTML 属性仍然写双引号**。

### 坑五：追加内容要同步改两处加载顺序，并迁移分组定义

在已有知识库上追加章节时，最容易漏的是"文件写好了，但引擎没加载"。**必须同步修改两处**，且顺序一致：

1. `index.html`：`<script src="data-xxxN.js">` 标签 + `merge()` 数组里的分片列表；
2. `export-md.js`：`new Function(...)` 的文件名数组 + 合并数组。

另外，**分组定义只能存在于一处**：新增末片后，把新的末片设为 `isFinalGroups: true` 并放进**完整的分组列表**（含前面所有分片的分组），而**旧末片的 `groups` 必须整块删掉**，不要留着"作历史备份"。

> 踩过的坑：旧末片的 `groups` 虽然因为 `isFinalGroups: false` 而不会被应用，但它会在校验器里被静默忽略、被维护者误读为"还有一处分组定义"，下一次追加时极易改错文件。**不变式要能被机器检查，而不是靠人记住。** `check-data.js` 已把"携带 `groups` 但未标 `isFinalGroups`"列为失败项。

漏改的表现是——新章节能搜到，但导航树里没有；或者导航分组顺序错乱。**改完必须跑一遍 `check-data.js`**，2/3 项交叉校验会立刻暴露疏漏。

> 合并分片时**按数字序**，不要按字母序：字母序会把 `data-xxx14.js` 排到 `data-xxx9.js` 前面，一旦有两处 `isFinalGroups` 就会选错分组。`index.html` 用显式数组顺序、`export-md.js` 用 `parseInt` 排序、`check-data.js` 也已改为数字序。

> **每个库各有自己的末片。** 一个 `index.html` 挂多个库（甲库 / 乙库 / 丙库 / …）时，`isFinalGroups` + `groups` 是**按库分别存在**的——实测四个库的分片里各有一个末片。追加内容时**只动涉及的那一个库**（把该库的 `groups` 从旧末片整块迁到新末片），不要顺手去清理别的库，也不要以为"全局只有一个末片"。迁移脚本的正则要**不依赖缩进与注释格式**：两个库的末片写法并不一样（有的 `sections: {` 带缩进、有的顶格，注释文案也不同），按缩进写正则会在第二个库上直接匹配失败。**迁移完必须断言旧末片只剩 `['sections']`。**

### 坑六：相邻加粗与"标签＋正文"，在 Markdown 里会粘连

HTML 里两种布局到了 Markdown 会丢信息，症状都在导出侧、不影响网页：

| 源 HTML | 直接转换的产物 | 渲染结果 | 修法 |
|---|---|---|---|
| `<b>注解 1</b><b>清理不等于消除</b>` | `**注解 1****清理不等于消除**` | 多数渲染器解析异常（`****` 不合法） | 标签间插入分隔符，或在导出时把 `****` 拆成 `** **` |
| `<div class="row"><b>失效环节</b>理化检验…</div>` | `**失效环节**理化检验…` | 标签与正文粘连成一句 | 导出时在标签后补全角冒号 |

第二种的根因：HTML 里 `.case .row b` 是 `display:inline-block; min-width:66px` 的**定宽列**，标签与正文天然分栏；Markdown 没有这个概念，必须显式补一个分隔符。判据是 `div` 的 class 含 `row` 且首元素为加粗、其后不是标点/空白。

**批量修数据用脚本，不要手改**——本次是 5 个文件 100 处：

```js
/* 把 <b>标签</b><b>标题</b> 改成 <b>标签</b>｜<b>标题</b>，跳过标签本身已以标点/空格结尾的 */
s.replace(/(<b>[^<]*<\/b>)<b>/g, function(m, left){
  const inner = left.replace(/^<b>/,'').replace(/<\/b>$/,'');
  return /[\s：，。、；！？·｜）】]$/.test(inner) ? m : left + '｜<b>';
});
```

`scripts/export-md.js` 里已内置两道兜底：`inline()` 把任何来源的 `****` 拆成 `** **`，`rowMd` 分支为 `.row` 补冒号。**改完必须回扫 `md/` 目录确认 `****` 计数为 0。**

### 坑七：插图的位置、安全与导出尺寸，三个都会翻车

**① 位置不能用绝对序号，要用 h2 关键词锚点。** 章节正文会增删，写「插在第 3 个 `<div class="blk">` 后面」必然错位。锚定为 `{ f:'figId', after:'二、程序推进' }`，引擎按 `html.split(/(?=<h2>)/)` 切段、找以 `<h2>` 开头且含该关键词的一段，append 到段尾。**锚点打不中必须 fail loud**——`check-figs.js` 把「锚点未命中」列为失败项，运行时兜底才允许退化为「插到章节顶部」。

**② 敏感图文一律「纯矢量 + 图案蒙版」，不得有真实照片。** 涉及尸体现象、损伤形态、窒息征象这类内容时：

- 人体只用几何图形示意（椭圆＋折线骨架），**不出现写实细节**；
- 敏感区域覆盖 SVG `<pattern>` 打码层，`patternUnits="userSpaceOnUse"`，三个灰度矩形交错（`#d7dce3 / #aeb8c4 / #98a4b2`），经 `fill="url(#mos-XX)"` 引用；
- **每个图独立 id 前缀**（`mos-pmi`、`mos-livor`…）——同一页有多张图时 id 会撞车，撞车后先出现的那张的图案会污染后面所有图；
- 图内显式标注「已打码」文字，卡片头部再加 `敏感内容已打码` 角标（由 `sens:true` 自动生成）；
- `check-figs.js` 会强制校验：`sens:true` 的图**必须有 `<pattern>`**、**必须 `url(#mos`**、**必须含「打码」字样**，且**不得含 `<image` / `.png` / `.jpg` / `data:image`**（杜绝偷偷塞位图）。

**③ 页内用 viewBox 自适应，导出必须补回显式宽高与白底。** 页内 SVG 只写 `viewBox="0 0 680 <h>"`（不写 width/height），才能 `width:100%` 随容器缩放；但**同一份 SVG 直接导出给 Word/PPT 会出事**——没有宽高会按默认 300×150 渲染成一条，透明背景在深色主题下会变成黑底。导出时必须：

```js
const vb=(svg.match(/viewBox="([\d.\s-]+)"/)||[])[1]||'0 0 680 360';
const [,,w,h]=vb.trim().split(/\s+/).map(Number);
svg = svg.replace(/<svg\b/, `<svg width="${w}" height="${h}"`)
         .replace(/(<svg\b[^>]*>)/, `$1\n<rect x="0" y="0" width="${w}" height="${h}" fill="#ffffff"/>`);
```

另外两个必查项：**SVG 内标签必须闭合配平**（`rect/circle/path/line` 等自闭合元素要按 `/>` 识别，否则误报），**`<g>` 多一个 `</g>` 不会报错但会让整图的缩放/平移错乱**——本次实测就是两张图各多了一个 `</g>`，肉眼完全看不出，靠脚本才抓到。还有 `figs*.js` 走的是**数字序**加载，与 `data-*.js` 同一套规则（见坑五）。

> 一句话：**图示层的所有不变式都要能脚本检查**（位置锚点、打码完整性、标签配平、导出尺寸），跑 `check-figs.js` 全绿才算完。

### 坑八：`desc` / `title` / `tags` 是转义渲染，写 HTML 会以字面文本显示

引擎对库与章节的元数据字段**分两类渲染**：

| 字段 | 渲染方式 | 能否写 HTML |
|---|---|---|
| `subtitle`、`footnote` | 原样插入（`lib.subtitle`） | 可以，`<b>` 会加粗 |
| `desc`、`title`、`homeTitle`、章节的 `desc`/`title`/`tags` | **转义渲染**（`esc(...)`） | **不行** |

在 `desc` 里写 `<b>启示、教训</b>` 不会报错，页面会把这串标签当普通文字打印出来，症状是**库总览标题下方那一行里冒出一串 `<b>…</b>`**（本次实测踩到）。章节卡片还会对 `desc` 做 `.slice(0, 86)` 截断，标签更会挤掉正常文字。

规则很简单：**`desc` / `title` / `tags` 一律纯文本，要强调就靠措辞，不要靠标签。** `check-data.js` 的「2b. 元数据转义字段校验」会反向拦截这三类字段里的 HTML 标签与尖括号。

## 第二批坑（运维期才暴露，v2.0）

前八个坑在**建库**时会遇到；下面这批在**改库、扩库、验证**时才冒出来，且大多**静默失败**。

### 坑九：单分片体积硬线 64 KB，切分要用「行号切片」不是字符串替换

实测阈值：**单分片 ≤ 64 KB**。而批量插入内容会推高体积——本次给一个库插 9 个口径块，61.4 → 64.5 KB 直接越线。处置：迁出末尾几节为新分片，并把末片改名为更大的编号以维持「末片编号最大」。

**切大分片用「按行号切片 + 重新包装」，不要用字符串正则替换**：SVG 与模板串里引号密布，正则很容易误伤。按行号把内容切成两段，各自拼上新头注释与 `window.X = { … }` 包装最稳。切完**必须 `node --check` 两个文件**，再跑 `check-figs.js` 比对图数（本次 147 张一张不差）。

### 坑十：无头探针页是 `index.html` 的一次性拷贝，改完必须重新生成

**症状**：Bug 明明已改好，复测仍报同样的错。
**根因**：探针页是从 `index.html` 复制出来的一次性快照，改的是源文件、测的是旧快照。
**纪律**：**每次改完 `index.html` 都要重新生成探针页再渲染**，否则会得出「改了没生效」的错误结论，白白排查半天。

### 坑十一：同一字段在两处用不同数据口径 = 不会被语法检查发现的运行时炸弹

实测：索引构建时把 `tags` 存成**字符串**（`(s.tags||[]).join(' ')`），打分逻辑却仍按**数组**用（`(x.tags||[]).join(' ')`）——对字符串调 `.join` 抛异常，**整条搜索链路静默失败**（面板不弹、无任何提示）。

**这类错误 `node --check` 查不出来，只有真跑才暴露。改数据结构时必须搜全所有消费点。**

### 坑十二：无头调试要在 IIFE 内暴露函数，别模拟 DOM 事件

试过并失败的三条路：① iframe + 跨源 `file://`（拿不到内部文档）② 注入 `dispatchEvent(new Event('input'))`（headless 下事件不可靠）③ 探针放 `</body>` 前 + `load` 监听（仍无反应）。

**成功做法**：在 IIFE 内写 `window.__search = doSearch`，探针直接 `try { window.__search(q) } catch(e) { 记录 e.message }` —— 能直接拿到真实异常。上面坑十一的 Bug 就是这样定位到的。

### 坑十三：编辑工具的替换锚点不要跨「结构边界」

实测：用「`</div></div>` + `<hr>` + `<!-- 四 -->` + `<h2 id="p4">`」整段做锚点，新文本漏写了后三行，**第四部分标题与注释被误删**。

**纪律：锚点不要跨越章节标题、注释分隔这类结构边界；改完立刻复查标题清单与目录锚点是否一一对应**（`grep -n "<h2 id="` 配目录里的 `<a href="#p`）。

### 坑十四：正则里的 `\s` 会被写成字面双反斜杠

`r'html\s*:'` 落盘后可能变成 `r'html\\s*:'`（匹配字面反斜杠），**静默返回 0 匹配且不报错**——曾致同一文件在两个脚本里得出相反结论（0 vs 6）。

**解法：正则一律不写 `\s` / `\d` / `\w`，改用显式字符类** `[ \t]`、`[0-9]`、`[a-z]`；含正则的脚本一律**写成文件执行**，不要塞进 `node -e` / `python -c`。

同理，**字段锚点正则要允许键名后的可选引号**：`html` 键有两种写法（模板串 `html: \`…\``、JSON `"html": "…"`），正确写法是 `html["]?[ \t]*:[ \t]*(["`])`——只写 `html\s*:` 会挡掉 JSON，只写 `"html"\s*:` 会漏掉模板串。**判风格看「冒号后的引号」，不看节 id 的引号**（存在「id 双引号 + html 模板串」的混合片）。

### 坑十五：要「求值数据分片」时，照抄既有脚本的加载方式

首版自己写了 `global.window = global; eval(src)`，结果根对象全取不到、统计全 0（**静默错，不报错**）。

**正确写法**：
```js
global.window = {};
new Function(fs.readFileSync(f, 'utf8'))();      // 不是 eval
// 从 global.window 取根对象，再按编号后缀收集分片（prefix_1 / prefix_2 …）
```
凡是要「求值分片」，先去看 `check-links.js` 或 `check-data.js` 开头怎么写的，照抄，不要另发明一套。

   - **跑校验之前先跑 `node build-bundle.js`**（改过任何 `data-*.js` / `figs*.js` / `syn-*.js` 之后）。校验脚本读的是源文件，不重建照样能全绿——那是假绿灯，页面其实还停在旧 bundle 上（见坑十七）。

### 报规模数字之前，先把口径对齐

交付说明和 README 里要写"多少字 / 多少专题 / 多少张图"，**口径不一致会凭空多出上千字**。本次实测同一个库有四种字数口径（含标签算、去标签算、去实体算、去空白算），**差 1—2 千字**。做法：**先查历史文档用的是哪种口径，用同一种算**，否则新旧数字无法比较。

另一个更硬的验收办法——**增量自洽**：

> 新增内容的「卡片块数」与「表格数」，应当**恰好等于**规模统计的增量。

本次实测：新增 10 节的 `blk case/note/warn/tip` 共 47 个、`<table>` 共 61 个，与总量变化 951−904=47、463−402=61 完全吻合。**这比看总量可靠得多**——总量对不上时，它能立刻告诉你是内容漏了还是统计脚本错了。

## 内容写作规范（决定质量上限）

- **每节首段给定位**：这一节解决什么问题、处在整个体系的哪一环。不要一上来就罗列。
- **结构化的关系画成图，别用文字描述**：流程、层级、分支、时间轴、对照矩阵这五类关系，配图讲一遍比写三段话有效。每张图必须带**图注（读图要点）**和**课堂用法（老师怎么用它）**——只给图不给读法，图就退化成装饰。图内文字要从简，超过 12 个字的句子挪到图注里。
- **结构化优先于叙述**：能用表格就不用段落，能用清单就不用长句。表格列名要具体（写「推断价值」而不是「说明」）。
- **区分四类信息**，用不同卡片承载：法条/规范原文（`blk source-ref`）、实例（`blk case`，固定「事实/处理/要旨」三段）、认知提醒（`blk note`）、禁止与红线（`blk warn`）、方法小结（`blk tip`）。
- **写"怎么用、错在哪"**：每条规则后跟一句实务口径或常见误区，这是知识库与资料堆的区别。
- **口径与免责必须落在页面上**：注明数据截止时点、权威来源、以及"整理稿不等于官方文本"。不要只写在 README 里。
- **敏感领域守住边界**：涉及执法、侦查、技术手段等主题时，只从公开教材与法规出发，从"识别与防范"角度写，不给操作性指引，并显式声明内容边界。**配图同样受此约束**——敏感题材只用抽象示意图＋打码层，不追求"还原度"。
- **历史沿革类内容（法制史、行业史、机构史）守住四条纪律**：
  1. **历史用来理解现在，不用来论证现在**——不拿"古已有之"当论据，不用结果的美好掩盖过程的复杂，不把立法技术的精密度等同于价值取向的正确。
  2. **区分史实与演绎**——影视、演义里的形象不等于史料。本次实测：「不良人」在荧屏上的样子与史料记载差别很大，必须在正文里直接点明，否则读者会把剧当史。
  3. **只讲公开的组织沿革、制度变迁、政策原则与已公开的经验**，涉及具体手段与技术方法的一律不涉及。
  4. **涉及旧法旧制必须逐处标注「已废止 / 不构成现行引用依据」**；**时效与效力分开写**——如"某修订草案正在征求意见"，必须同时写明"**草案不产生法律效力**，现行有效的仍是某某年制定（某某年修正）的版本"。
- **传承类结论要可操作**：写"哪些可以借鉴、哪些不能照搬"时，两边都要落到具体制度上，不能停在"取其精华去其糟粕"。给一份**判断框架**（本次用的是三步：① 与现行宪法法律原则冲不冲突 ② 今天还有没有效 ③ 它是"做法"还是"价值"），再附正反各一个检验例子。

### 判例 / 案例型内容的四栏卡片法

做"经典判例库""案例集"这类内容时，**每个案件固定四栏**，这是本技能验证过最有效的组织形式：

```
案情与裁判要旨  →  启示  →  教训  →  对个人成长的教育意义
```

- **案情与裁判要旨**：只留与法律判断有关的事实；裁判要旨写成一句话「在 X 情形下，应当适用 Y 规则，因为 Z」。
- **启示**：这条规则**为什么**这样定，它保护了谁、约束了谁。
- **教训**：当事人或社会在**哪一步**做错了选择；换一种做法代价能否避免。
- **对个人成长的教育意义**：把法律语言翻译成成长语言（证据意识 / 边界意识 / 责任意识 / 诚信品格 / 纠错能力 / 扶助责任 / 公民勇气），并给出**可以日常训练的动作**，不要停在"要遵纪守法"。

**三条硬规矩**：
1. **案件事实必须核过再用**。指导性案例编号、案号、年份、判赔数额是最容易记错的部分——本次实测就发现「指导案例第 50 号」常被误当作冷冻胚胎案（实为人工授精继承纠纷案），而冷冻胚胎案是 **2014 年度人民法院十大民事案件**之一、二审案号 `(2014)锡民终字第01235号`。**凡不能核实的一律不写编号**，宁缺勿造。
2. **标注适用法律的时点**。涉及《民法典》施行前的案件，写明当时适用的是《民法通则》《继承法》《婚姻法》等，并在库的 `footnote` 里提示"不得直接用于今天的规范引用"。
3. **区分"已依法纠正"与"正在争议"**。写冤错案时明确其已被依法纠正、纠正本身是法治进步的体现；不要写成对司法的质疑。

## 每节的「口径声明」块：把时效风险结构化（v2.0）

强时效领域（法律、政策、标准、医学指南）最大的风险不是「写错」，而是**「写对了但已经过期」**。读者拿一条过期条文去用，后果比查不到严重得多。

**做法：每个节正文起始处插一个统一的结构化容器**，说明依据什么整理、以什么为准、引用前去哪里核验：

```html
<div class="blk scope"><div class="bt">📌 本节口径</div>
<p>本节依据……整理，以……为准。引用前请到……核对最新文本与施行日期。</p></div>
```

**为什么用容器而不是一句话说明**——踩过的实测教训：初检用「正文里是否出现 20xx 年」做判据，得出 47% 覆盖率，**属误报**，它把案例叙事里的**案发时间**（「2017 年 5 月 2 日上午 9 点多」）也算成了时效标注；改用严口径（必须存在容器本身）后真实值只有 **22%**。

> **通用结论：只要判据是「字符串像不像」，就一定有误报。** 要机器能精确判定，判据必须是结构化容器，不能被正文表述干扰。

**按库分套措辞**（同一库内完全一致，便于批改与检索）。例：主库指向权威来源核对；案例类库声明不构成个案定性；创作类库声明以检索时点为准；沿革类库区分「沿革」与「现行」并说明旧制只用于理解现在；流程类库强调期限数字须核对原文。

**必须固化成硬拦截**：`check-data.js`【7】——任一章节缺容器、或重复插入 ≥2 个，校验报错退出（`process.exit(1)`）。**新写的节不带标注就过不了校验，规则不靠记性，靠脚本。**

## 检索语义近似层：让口语也能搜到（v2.1）

关键词匹配有个结构性问题：**读者用的是自己的话，库里写的是规范术语**。搜「防卫」只能找到含「防卫」二字的节；读者想问「对方欠钱不还怎么办」，脑子里没有「民间借贷」；想问「公司把我开了」，想不到「违法解除劳动合同」。

离线单页跑不了向量模型，但用**同义词表 + 口语问法映射**可以做低成本近似，效果足够好。

**先分层，再写词表（v2.1）**：引擎与数据必须拆成两个文件，否则换领域就得重写逻辑。

| 文件 | 角色 | 换领域时 |
|---|---|---|
| `scripts/syn-core.js` | **引擎**（领域无关）：通用噪音词、七类通用疑问识别、带权重的展开算法 | 一个字不用改 |
| `scripts/syn-data.example.js` | **数据**（法律域示例）：109 词条 + 50 整句 + 领域噪音词 + 疑问落地 | 必须重写 |
| `scripts/syn-data-shebao.example.js` | **数据**（社保域示例，约 40 条，仅示范结构） | 结构参考 |

**四路扩展，各带置信权重**（权重决定它能给结果加多少分）：

| 来源 | 例 | 权重 |
|---|---|---|
| ① 整句映射 | 「公司把我开了」→ 违法解除 / 解除劳动合同 / 经济补偿 | 1.0 |
| ② 词级精确命中 | 「辞退」→ 解除劳动合同…（双向反查） | 1.0 |
| ③ 子串兜底 | 整句含词条但切不出词（无分词库），只认 ≥2 字的键 | 0.35 |
| ④ 通用疑问意图 | 要多久 / 多少钱 / 去哪办 / 要什么材料 / 什么条件 / 不服 / 加急 → 由领域表落地 | 0.75 |

**排序必须打分，不能两段拼接。** 初版把结果分成「原始命中段 + 扩展命中段」拼接，问题是**扩展段内部无序**，会被正文里偶然出现的同义词把无关节顶到前面。

**三条打分纪律（每条都是实测踩出来的）**：

1. **原文命中要分档**，不能一律满分。整句口语在案例正文里很容易偶然出现一次，若因此给最高分，收录了全部口语的汇总页（对照表、导读）会霸榜——实测 18 条里 6 条首位被它占住。改为：标题含 100 / 标签含 50 / 描述含 40 / 正文含 20。
2. **扩展词命中各乘权重**：标题 40 / 标签 22 / 描述 14 / 正文 6，再乘来源权重。正文档只给基础分——汇总页什么词都有，给高分会被它刷上去。
3. **通用疑问只作强化，不能单独把一节顶上来**。问「劳动仲裁要多久」曾被标题写着「办案期限」的治安那节抢走——读者问的是劳动争议，不是治安。规则：读者说出了具体事由时，疑问词只在该结果**已命中事由词**时加分（且打折 0.3）；读者没说事由时（如「不服一审判决」），疑问词才允许独立生效。

**指路节折让**：标题或分组含「导读 / 对照表 / 入口 / 索引 / 导航 / 速查 / 自测」的结果打 **0.2 折**（v2.0 为 0.45，实测不够——汇总页基础分太高，0.45 压不住）。它是路标不是内容，**只降权、不剔除**：读者的话确实只能由指路节解释时，它仍应出现在结果里。

**给读者看见系统做了什么近似**：命中扩展词时，面板顶部显示「把「公司把我开了」理解为 **违法解除 / 解除劳动合同 / 经济补偿** 检索」，具体条目再带「同义：×××」标记。不要让语义层变成黑箱。

**造词表的三条经验**：
1. **词条不要凭空编**——从「读者实际会怎么说」里捞。本次是从库里已有的「大白话对照表」一节反推，所以每条展开都对应真实存在的内容，不会出现「展开后查不到」。
2. **双向反查必须做**，否则读者搜规范词时口语侧的节就搜不到。
3. **噪音词分两层**：纯语言层（怎么办 / 我想问 / 能不能…）在引擎里；领域层（如社保域的「能报吗」）在领域表里补。

**改动后必须回归**：语义层的每次调参都可能让原本正确的查询退化（实测「降低正文命中权重」一改，就曾让「老赖不还钱」从执行程序退化成违约金）。固化一组口语查询作为回归集，改一次跑一次，首位退化了就撤回。

**★ 键与查询必须统一小写口径（v2.2.1 修，典型的「静默失效」）**：查询在进 `expand()` 前会被 `toLowerCase()`，而 `Object.keys(词表)` 保留原样——**凡含拉丁字母的键（`N+1` / `2N` 这类）全都匹配不上**：表现是「扩展词为空、`hasCore=false`、首位直接落空」，看上去像「库里没有这个内容」，其实是词表键根本没被匹配到。修法＝建一份「小写键 → 原键」映射，然后**查表、双向反查、子串兜底、键进位四处一律按小写比对**——只改一处，别的入口照旧漏。

**★ 词表的「缺键」比「缺值」隐蔽**：同一个词，**有键和没键是两回事**。没键时它只能靠别的键的**值**间接命中；若那些值恰好是泛词，泛词所在的那一节就会被顶到首位。自查两件事：① 把「读者会直接打出来的词」逐个当键过一遍；② 看**明显对称的一对词是否都有键**（有 `法院` 却没有 `检察院`，就是典型漏网）。

**★ 一条最容易算漏的规则：映射值若与查询字面重合，会被 `add()` 跳过**（原文命中已经计过分了）。所以给「A 和 B 有什么区别」配 `['A','B',…]` 等于没配——两个值全被跳过，能进扩展词的只剩其余的非查询词，而它们往往正是泛词。

**★ 判「库里没有」之前，先分清是「没有内容」还是「没有入口」**：两者的修法完全不同。实际项目里**入口缺失比内容缺失更常见、也更隐蔽**——数字/规则散在别的节里，读者却问不到，检索看起来就是「没这个答案」。补一个入口节的成本远低于补一套内容。

**边界要说清楚**：这是规则驱动的近似，不是真语义理解；词表需手工维护，表外新说法仍退化为关键词匹配。另外，**检索调不出不存在的东西**——口语测试集扩大后暴露的内容缺口（库里根本没有对应的节），只能靠补内容解决，不要试图靠调排序掩盖。

## 第三批坑（改库期才暴露，v2.2）

前两批坑集中在「怎么建起来」，这一批集中在「建完之后怎么改」——都是**安静地坏**，不报错、不白屏，只是慢慢不对了。

### 坑十六：库里可能并存三种「节写法」，批量插入脚本先认清是哪一种

同一个知识库目录里，章节的写法往往不是一种，而是三种并存，各自的字符串规则完全不同：

| 写法 | 长相 | 危险点 |
|---|---|---|
| 模板串 | `html:\``…\`` ` | 内含 `"` 不需要转义，但**不能出现反引号与 `${`** |
| **JSON 双引号** | `"html": "<div class=\"blk note\">…"` | html 值是**单行字符串**，内层每个 ASCII `"` 都得写成 `\"` |
| 紧凑单引号 | `'sec-xxx': { title: "…", html: '…' }` | 字段不带 key 引号，容易和 JSON 那一路搞混 |

往第二种（JSON 双引号、html 单行）里插入一段多行块，若直接把**真换行 + 裸 `"`** 塞进去，一行就把 JS 字符串截断，页面白屏。
`node --check` 的报错只有一句含糊的 `Invalid or unexpected token`，**报错位置和真实原因离得很远**，肉眼看代码也看不出。

**补引号是修不好的，得把插入区整体重建为单行转义文本**：真换行 → `\n`，ASCII `"` → `\"`，然后再拼回去。三步定位别省：

1. 从本节 id 的位置往后（`s.index`，不是全文 `rindex`——全文最后一个 html 键几乎一定不是你要的那节）找到**本节内第一个 `html` 值的起始引号**；
2. 在该值内找**第一个真换行**，往前吃掉它前面的转义 `\n`（`b0 = nl` 或 `nl-2`）；
3. 从该处往后找**其后紧跟 `,` 或 `}` 的第一个未转义 `"`**，那才是终止符，之后原样保留。

> 判据写成「其后去空白紧跟 `,` 或 `}`」是关键：html 值里本来就有 `class="…"`，只认「下一个引号」会命中属性里的那个。

### 坑十七：源文件是唯一数据源，`bundle/` 是生成物

内容文件攒到一百多个 `<script src>` 之后，首屏要发一百多个请求。打包成 `bundle/` 十来个文件即可，**但要立死规矩**：

> 源文件是唯一数据源，`bundle/` 是生成物。**改完任何 `data-*.js` / `figs*.js` / `syn-*.js`，必须重跑 `node build-bundle.js`。**

忘了重建的后果最阴：**页面停在旧 bundle 上，而三件套校验照样全绿**——因为 `check-data` / `check-links` / `check-figs` 读的全是根目录的源文件，它们根本不知道页面读了什么。这就是「看起来没问题其实没生效」。

打包脚本要满足两条，否则不用：

- **幂等**：从现存 bundle 头部的「合成自：」清单**反解回源文件列表**再重建，重复跑不会越滚越多（不然每跑一次标签就多一层）；
- **收尾等价性自检**：逐个源文件求值 vs 逐个 bundle 求值，比对全局对象的 JSON 与函数 arity，不一致直接非零退出。

`scripts/build-bundle.js` 是**泛化版**，分组靠架构规则推断，换库不用改代码：`syn-core` → engine、`syn-data` → word-main、`syn-data-<域>` → word-<域>`、`figs*` → figs.js、`data-<域>N` → data-<域>。实测 135 个源 / 0 未归类 / 11 个 bundle。

### 坑十八：校验器读源文件、页面读 bundle —— 「全绿」只证明校验器绿

`check-data.js` 的「分片是否挂载」是靠**扫 `index.html` 的 `<script src>` 标签**实现的。一打包就失配：标签没了，于是误报「135 个分片全部未挂载」——**校验器自己没坏，是它的视线被打包这件事挪开了**。

改成对 `bundle/x.js` 头部清单做反解即可。这条值得单列，因为它是个**元方法论**：

> 一个项目里有多套校验器各有各的视线范围时，「全部绿灯」只证明**这些校验器**看到了它们各自那段，不证明**交付物**是对的。
> 两套视线一旦错位（校验读 A、运行读 B），绿灯就失去了对页面的证明力。

### 坑十九：改了 bundle 命名规则，`index.html` 还停在旧名 —— 三件套全绿，页面全站失效

坑十七讲「改完源文件忘重建」。它的镜像更狠：**脚本重建了，但产物换了名字，而 `index.html` 还指着旧名。**

实测一次：把命名规则从 `syn-core → engine-core.js` 改成 `syn-core → engine.js` 后重跑，
脚本一路绿灯（135 源 / 11 bundle / 等价性自检 136 个全局对象全对，返回 0），`bundle/` 里也确实是新名文件，
**但 `index.html` 里那两个 `<script src>` 还是旧名**。后果：

- 页面照常打开、导航照常渲染（那是 `index.html` 自己的脚本在跑）；
- 但引擎与词表 **404 加载不到** → **全站检索静默失效**（输入什么都出不来，看着像「库里没这个内容」）；
- `check-data` / `check-links` / `check-figs` **一个都不报**——它们读的是源文件（坑十八的同一条视线错位）。

根因是一个不起眼的实现选择：回填阶段对**已经是 `bundle/xxx.js` 形式的标签一律原样保留**
（这正是「幂等」的实现方式——首轮折叠完就不再动）。于是「命名规则」被固化成了 `index.html` 里的字符串，
而脚本改了规则不会回头核对。**幂等和自检，恰好都覆盖不到这个方向。**

修法两条，都要有：

1. **回填时反推正确名**：从旧 bundle 头部的「合成自：」清单算出它**现在**该叫什么，与标签里的名字不一致就改正（自愈），
   并在日志里打印「发现 bundle 命名漂移：a → b」。这一步必须在**删旧产物之前**做——删完就反解不出来了。
2. **标签指向本轮没生成的 bundle 名时直接报错退出**：宁可打断，也不能静默留一个死链。

`scripts/build-bundle.js` 现含此检测（自测 ⑦ 守这条：先把 `index.html` 指回旧名、再跑一轮，必须自动改正且返回 0）。

> **通用判据**：凡「生成物 + 引用方」的体系，**改生成器时必须检查引用方**。
> 三件套全绿 + 等价性自检全绿 + 页面能打开，三条证据都在，唯独「页面要调用的东西真的存在吗」没人问——
> 这是最贵的一类假绿灯。**真机无头跑一次检索（必须出 hit）是唯一能兜住它的验收**（见打包工序的验收三段式）。

## 打包工序：源文件唯一数据源 + bundle 生成物（v2.2）

**什么时候做**：内容稳定、校验跑通之后。建库期就打包只会给自己添堵（每次改内容都要重建），建议在「执行清单」第 11 步前后做一次。

### 分组规则：换库不用改代码

`bucketOf(文件名)` 只按架构规则推断，不写死任何库名：

| 文件名 | 归入 bundle |
|---|---|
| `syn-core.js` | `engine.js`（**领域无关引擎，一个字都不要动**） |
| `syn-data.js` | `word-main.js`（主域词表） |
| `syn-data-<域>.js` | `word-<域>.js`（第二域词表，如社保域，可在页面上切） |
| `figs1.js` … `figs-map.js` | `figs.js`（**前缀规则要用 `figs*`，只写 `figs\d*` 会漏掉 `figs-map.js`**） |
| `data-topicA7.js` / `data-topicB3.js` | `data-topicA.js` / `data-topicB.js`（去掉末位分片号） |

> 这条是踩过才补的：自测时规则写 `/^figs\d*$/` 一切正常（迷你项目里没有 `figs-map.js`），搬到真项目一 dry-run 就露馅——`figs-map.js` 归不了类，脚本直接报错退出。**自测样本必须贴近真实结构，否则自测通过什么也没证明。**

### 打包前：把项目私有值抽成配置层（不只是「删干净」）

校验与导出脚本最初都是「为一个库写的」，很容易写成这样：

```js
const LIBS = [
  { name: '甲库', root: global.window.TOPIC_A_DATA, prefix: 'TOPIC_A_DATA' },
  { name: '乙库', root: global.window.TOPIC_B_DATA, prefix: 'TOPIC_B_DATA' },
  // …
];
```

这样的脚本**本机能跑、别人装上就崩**：换个知识库，库对象名不同，脚本要么报「缺少 XXX_DATA」，
要么静默少检查几个库（比崩溃更糟）。而且项目私有的节 id 清单会被原样打进包分发出去。

**正确做法是抽配置层，而不是把参数删掉**（删了就变成不可用的包）。三层取值：

| 层 | 载体 | 是否随包发布 |
|---|---|---|
| ① 自动探测（默认） | 读 `index.html` 里 `LIBS.push(window.XXX)` 的顺序 = **库序的唯一权威来源** | 是（逻辑） |
| ② 项目私有值 | 同目录 `kb.config.json`（库显示名、输出文件名、图示标签映射） | **否** |
| ③ 项目私有断言 | 同目录 `project-checks.js`（某个库应含哪些节、subtitle 口径…） | **否** |

`scripts/kb-config.js` 就是这三层的实现，校验与导出脚本全部改为从它取值：

```js
const KBC  = require('./kb-config.js');
const LIBS = KBC.libs(dir, global.window);   // [{ idx, root, prefix, atlas, name, raw, sections, groups }]
const PC   = KBC.projectChecks(dir);         // 取不到返回 null → 该段整体跳过
```

**两个容易踩的实现细节**：

- **必须合并分片后再判定「这个库存不存在」**。很多库的**根分片 `sections` 是空的**，章节与分组都在后续分片里；只看根分片会把整个库误判为「不存在」而静默漏检。
- **库序别猜，去读 `LIBS.push`**。按脚本加载顺序或文件名字典序推断，在多库项目里都有反例（bundle 顺序 ≠ 库序）。

### 幂等与等价性自检

```
node build-bundle.js              # 重建 + 等价性自检，失败非零退出
node build-bundle.js --self-test  # 自测七项：分组 / index.html 收敛 / 幂等 / 坏源文件必须报错 / 返回码 / 命名漂移自愈
```

脚本把每个 bundle 的头部写成 `合成自：a.js、b.js、c.js`，下次运行据此反解回源文件清单重建，所以**重复跑不会越滚越多**；反解的同时顺手算出这个旧标签**现在**该叫什么，与标签里的名字不一致就改正 `index.html`（见坑十九）；收尾把逐源求值结果与逐 bundle 求值结果比一遍（全局对象 JSON + 函数 arity），不一致就报错。

### 打包后的验收三段式（缺一段都不算验完）

1. **DOM 逐字符比对**：打包前后各跑一次无头渲染，把 `<script>…</script>` 抠掉、空行去掉，**逐字符相同**才算没换皮。「两边都跑通了」不等于「两边一样」。
2. **等价性快照**：`build-bundle.js` 的等价性自检（全局对象 JSON + 函数 arity）。
3. **真跑一次功能**：`doSearch` 在 IIFE 里，外部调不到。探针页里给输入框赋 value 再 `dispatchEvent(new Event('input'))`，从面板结果读 `data-go`，确认几条口语查询的首位没变。

> 第 3 条专治「拼对了但拼错了」：等价性只证明值一样，不证明运行路径上有什么副作用被合成顺序影响了。

### 打包后要跟着改的地方

- **`check-data.js` 的「分片是否挂载」**：改成从 bundle 头部清单反解，否则误报全部分片未挂载（见坑十八）；
- **`check-*.js` 本身不用动**——它们读源文件，本来就该读源文件；
- **`export-*.js` 不用动**——导出走源文件，与页面读 bundle 是两条路。
