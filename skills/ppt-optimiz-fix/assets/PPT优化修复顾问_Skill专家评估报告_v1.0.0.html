贰二、逻辑性与内部一致性核检

2.1 数据流一致性 ✓

  • inspect_pptx.analyze(path) → dict 为唯一事实源，含 meta / structure / detail / font_plan / pyramid / image_text / ai_tell / aud 八大块。
  • report_pptx.py 仅消费 analyze() 输出，不重复解析 PPTX —— 单一事实源，无双份逻辑漂移风险。
  • run_all.py 通过 sys.executable 调用同级脚本，保证环境（venv）一致，避免系统 python 缺包。

2.2 自动信号逻辑核验 ✓（抽查通过）

  • ROI 检测：ROI_TERMS 含 投资回报/回收期/收益率/ROI/NPV 等；首次命中即记页码与词，证据可定位。
  • CTA 收口：标题命中 CTA_TITLE_HINT（下一步/行动/Q&A/计划/分工…）或 本页同时出现 OWNER_KEY_SET∩TIMELINE_SET 才判定——避免单页误报。
  • 管理者语言：MANAGER_TERMS 密度计分，≥阈值才加受众适配分。
  • 报告侧：ROI/CTA 缺失直接生成 P1 缺陷项（逻辑/说服力维度），证据文来自检测输出，推理链闭合。

2.3 已知不一致（需修） ⚠

  • report_pptx.py 第 310、312 行评分卡维度说明仍写「需人工复核」，与 HTML note 已声明的「已接入自动信号，人工复核仅作兜底」矛盾。属文案遗留，不影响功能，但损害专业一致性。
  • ROI 数值真实性仍依赖人工确认（脚本仅检测"是否存在量化页"，不核验数值真伪）——这是合理边界，应在文案中明确标注而非含糊。
建议：把评分卡维度说明改为「已接入自动信号（ROI 页 / CTA 收口 / 管理者语言），数值真实性人工兜底」，与 note 对齐。改动量极小。
